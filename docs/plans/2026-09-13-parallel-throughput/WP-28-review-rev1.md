## 阻断项

### B40（S4 结构面失效）：整块可被围栏成 code block，判据全绿

S4 只检查「冻结列表行自身缩进是否 ≥4 空格」与「列表是否被空行断开」，
没有检查**块是否落在代码围栏内**。在标题后插入一行 ``` ：

```
## Re-freeze 规则（编排者冻结前自检）
```
```

冻结分句一字未改、缩进未变、列表未断，`_inv_n_violations()` 返回 **[]（全绿）**。
但渲染后整节变成代码块，规范条目降级为示例文本，规范约束力归零。

这与 WP-25 的 B39/WP-26 的 B35 同族：**结构面只钉了行内形态，没钉块的渲染语义**。

复现：
```python
o6 = real.replace(SECTION_RE_FREEZE, SECTION_RE_FREEZE + "\n```")
_inv_n_violations(o6)  # -> [] 逃逸
```

### B41（S5 处境面覆盖不足）：去规范化句可插在**块内**，判据只守块前

S5 只把「标题的紧邻前一非空行」纳入冻结（`PRE_LINE_RE_FREEZE` /
`PRE_LINE_ACCEPTANCE`），块**内部**任意位置插句子完全不设防。在 oracle 第 4 项正文前插入
`（下列第 4 项为历史遗留，不再要求）`：

- 冻结片段三条**全部仍逐字在块内** → S2 过
- 极性分句原样存在 → S3 过
- 结构行未缩进未断开 → S4 过
- 标题前一行未动 → S5 过
- `_inv_n_violations()` 返回 **[]（全绿）**

第 4 项的规范力被块内一句话剥掉，测试 diff 为空。这正是我在冻结前存进记忆的
`surroundings-can-denormalize-unchanged-bytes` 那条 —— 只是这次去规范化句落在块内而非块前，
判据的处境面按「块前一行」建模，天然漏掉块内。

### B42（数量口径未冻结）：「四项证据」可被改回「三项」，第 4 项沦为孤条

`oracle 校验四项证据` 这句里的**数量词没有进任何冻结常量**。改成「三项证据」后：

- 第 4 项条目本身还在（S2 三条片段全过）
- 判据 **全绿**

结果是模板自我矛盾：抬头说三项，底下列四条。真实后果不是排版问题 ——
执行者按抬头的「三项」执行，第 4 项就是死条文，而门禁不会响。
本 WP 的全部目的就是让第 4 项有约束力，这一处逃逸直接击穿目的。

## 次要项（不阻断，但需处置）

### B43：`_section_block()` 用了 brief 明令禁止的 `text.index()`

Brief §A 的 S1 行写明「不得用 `text.index()` 取首个」。
`tests/test_wp_template_dispatch_lint.py:314-315` 两处用的正是 `text.index()`。

当前**尚未**造成逃逸，因为 S1 的唯一性检查先跑、`count != 1` 会先判红，
诱饵块进不到 `_section_block()`。但这是**靠执行顺序侥幸成立**，不是靠结构成立：
S1 的唯一性用 `ln.rstrip() == title` 逐行精确匹配，而 `text.index()` 是子串匹配，
两者的匹配面不同 —— 一旦出现「S1 认不出、`index()` 认得出」的形状（例如标题行带尾随
可见字符），切块就会切到诱饵。

按「判据不能靠另一处检查的副作用成立」的一贯尺度，这处应改为
`re.finditer` 枚举全部出现并在 `count != 1` 时直接拒，与 S1 共用同一匹配面。
