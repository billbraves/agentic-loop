## 2. 三轮是不是同一个根因

是。三轮全部落在**同一个命题**上：「测试必须钉住三条纪律正文的**语义**，
使得削弱纪律必须在测试文件的 diff 里可见」。

- B20：钉住了 label，没钉住 **how**（正文可掏空）
- B28：钉住了 how 的**存在**，没钉住 how 的**极性**（可改写成相反规则）
- D1：钉住了极性，但**定位**不唯一（可插 decoy 块，锁读到 decoy，真实块随便改）
- D2：钉住了内容，但**结构**被归一化吞掉（删列表前缀 / 插空行 / 缩进成 code block 全绿）

四环是一条链：**锚点粒度 → 语义极性 → 定位唯一性 → 结构完整性**。每轮修掉一环，下一环露出。

这与 WP-26 的四环（声明路径 → 分支覆盖 → 约束强度 → 读取同一性）**结构完全同型**：
两者都是「我把一个多环不变式当成点状检查来冻结，一轮只冻一环」。

## 3. 我的计划面失误

### 失误 1（与 WP-26 §3 失误 1 同型）：按缺陷编号冻结，不按不变式冻结

三轮 brief 各以一个台账编号为标的（B20 / B28 / D1+D2），每轮范围只够修那一个编号。
正确做法是一次性把**不变式**写成验收标的：

> **INV-P（纪律锁定不变式）**：任何使三条纪律的**规范力**减弱的模板改动 —— 无论通过
> 删正文、改极性、改措辞、改结构、改定位，还是新增同形正文 —— 都必须使测试转红，
> 且转红只能通过修改测试文件里的冻结常量来解除（即：给削弱开绿灯必须在测试 diff 里可见）。

按 INV-P 冻结，D1/D2 在 rev2 就会被同一条验收要求捕获，因为 INV-P 里「改结构」「改定位」
是明文枚举的攻击面，而 B28-scoped 的 brief 只要求「极性反转必须转红」。

### 失误 2：我的自检变异集与判据的攻击面不同构

三轮我都亲自跑变异（这部分做对了），但**变异集始终由「上一轮的缺陷形状」生成**，
而不是由「本轮判据的结构」生成。rev3 的判据是「切块 + 归一化 + 逐字比对」，
它有三个可攻击面：切块（定位）、归一化（结构）、比对（内容）。我只攻了比对。

**应固化为常规**：给一个判据做自检时，变异集必须按判据自身的**每个组成步骤**各生成一组，
而不是按上一轮的缺陷清单生成。这是一条比「多测几个形状」更强的机械规则。

### 失误 3：`_normalize` 的强度没有被单独论证过

`" ".join(text.split())` 是 rev1 为治 B10（折行误红）引入的解药，三轮 brief 都把它写成
「必须的一步，不是可选优化」，但**从未论证它抹掉的东西是否都无害**。它实际抹掉的包括：
列表前缀相对正文的位置关系、空行分段、缩进层级（Markdown code block 归属）。
这三样都承载语义。**解药本身需要一条独立的正当性论证，而不是只写「少了它会误红」。**

## 4. 一条跨 WP 的观察（超出本 WP）

（多环不变式被当成点状检查冻结）。这说明问题不在这两个 WP，而在**我的冻结方法**：
我默认「一个 brief 对应一个台账编号」，而台账编号是**发现顺序**的产物，不是**不变式**的划分。

   与任务 #23（学习回边机械化）合流。
2. **判据自检的变异集按判据的组成步骤生成**（§3 失误 2）。这条应落到
   `docs/agentic/templates/WORK_PACKAGE.md` 的 oracle 三项旁边，作为第四项要求。

## 5. rev4 的范围裁定（本次复核的决定）

**裁定：rev4 按 INV-P 一次性收口「定位唯一性」与「结构完整性」两环，并把验收标的
从缺陷编号改写为不变式。范围仍限 `tests/test_orchestrator_protocol_disciplines.py` 一个文件。**

理由：两条逃逸同属「判据的非内容面」，同一个 `_cut_discipline_block` + `_normalize` 组合
产生，只修一条则另一条仍在；且这已是第 3 次 re-freeze，按点状修法继续切分只会招来第 4 次。

rev4 应包含：

1. **定位唯一性（治 D1）**：切块前枚举 start / end 标记的**全部**出现位置，各自要求恰好 1 次；
   并校验三块按预期顺序、互不重叠。变异用例：在真实块前复制一份完好冻结块，再反转真实块，
   断言因「边界不唯一」转红。
2. **结构完整性（治 D2）**：起始标记纳入完整列表前缀（`- **Criteria sourcing.**` /
   `- **Read-face pinning.**` / `- Every negative assertion` —— 编排者实测三者在活树模板中
   各恰 1 次出现，作为标记不引入歧义）；并在保留空白归一化的同时增加结构断言，
   拒绝块内新增空段、code block 或其他改变 Markdown 归属的格式。
   变异用例：删列表前缀、插空行、缩进成 code block 各一条，全部转红。
3. **`_normalize` 的正当性论证进 docstring**：明确写出它抹掉什么、为什么那些无害、
   以及哪些结构变化由第 2 项的结构断言而非归一化来把守。
4. **不回退** rev1/rev2/rev3 已通过的判别力：锚点断言、掏空守卫、三种极性反转、
   两条无害编辑反向探针、fail-closed 切块、纯内存变换（不写活树模板）。

明确**不**纳入 rev4（避免范围膨胀成第 5 次返工）：
- 模板措辞改动 —— `CLAUDE.md.tmpl` 仍是 forbidden。判据的职责是钉住被判对象。
- §4 的两条流程固化 —— 另立任务。
- `CONTRACT_TEMPLATE_VERSION` 不再 bump（已是 `"7"`）。

## 6. 实测证据（编排者本轮独立复现，不采信任何一方转述）

**D1（decoy 块）**：取 `criteria_sourcing` 块，把真实块的 `may only` 改为 `may also`
（极性反转），并在其前插入 `- ` + 原块 + 其 end marker 作为 decoy。结果：
`_assert_discipline_verbatim` **GREEN**、`_assert_discipline_anchors` **GREEN**，
而攻击后模板里真实纪律确实写着 `may also`。基线（未攻击模板）三条纪律全绿，正向可达。

**D2（结构变化）**：四种形状全部 verbatim=GREEN 且 anchors=GREEN ——
① 删 `criteria_sourcing` 的 `- ` 前缀 ② 删 `read_face_pinning` 的 ③ 删 `negative_assertion` 的
④ 把块内一句缩进 6 空格变成 code block ⑤ 块内插空行。

**修法可行性**：活树模板上三对边界标记各恰 1 次出现
（criteria start/end=1/1、read_face=1/1、negative=1/1），三块区间
`[2885,3288)` / `[3290,3820)` / `[4232,4629)` 有序不重叠；含列表前缀的三个候选起始标记
各恰 1 次出现。故 §5 的两项修法在当前模板上均可实施，不引入歧义。

**顺带校正一处 rev3 brief 的数字对应**：归一化后块长实测为
criteria=392、negative=386、read_face=515。codex 判词里「392/386/515 应理解为
criteria/negative/read-face」的推断正确。
