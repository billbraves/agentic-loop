## 一、先更正我自己的一句判断

我在 rev6 审核的收尾对用户说：「连续两轮都是判据本身有洞，而非执行者失手」。
**这句对 rev6 不成立**，实测如下：

```bash
cd /Users/admin/vibe/wp29-render-scope-decision
git show e2c483d:docs/plans/2026-09-13-parallel-throughput/WP-29-scope-decision.md \
  | /usr/bin/grep -n '五轮\|零重跑'          # -> 无输出
```

`:517` 那句「本 rev 是五轮里唯一不动证据的一轮（零重跑、零新命令、零新输出）」在 rev5
**根本不存在**，是 rev6 自己新写的。INV-S1 明文覆盖它（「不得依赖当前是第几版」+「须与
现行内容同真」），brief 的穷举义务也明文要求扫描后逐一裁定。所以 rev6 的阻断项是
**执行者在已冻结判据的覆盖范围内自制的新违反**，不是判据漏面。

这个更正很重要：它决定了 rev7 该不该改判据。**不该。** INV-S1 本身是对的、封闭的、
已经生效的——它抓住了一处它自己被引入后才产生的违反，这恰是不变式该有的表现。

唯一真正属于判据设计问题的是 M2（见第三节），范围是一行标题，且我在 rev6 签名里已明确
不把它计入返工面。

## 三、M2：判据内部的真实张力（这一处归我）

`:458` §6.1 标题「`rev1 → rev3`（上一轮，已提交 `e493c2a`）」。该标题在 rev4（`f1eee7e`）
写入，那时「上一轮」相对 rev4 为真；相对 rev6 已不真。

于是 rev6 的判据在**同一行**上给出相反指令：INV-S1 要求收口，判据 6（§6.1/§6.2 逐字保留）
要求不动。执行者按判据 6 不动，是对的；但这个冲突是我冻结时留下的。

**解法（须写进 rev7 的判据，不是留给执行者裁量）**：把 §6.x 的历史记录正文从 INV-S1 的
适用面里**显式豁免**，理由与双签名对 §2–§5「本轮」的一致判断同源——历史条目描述的是
**该条目自身主题那一轮**的语境，不是文件的现状自述。豁免后 `:458` 合法保留，冲突消失。

这条豁免不削弱 INV-S1：它缩小的是适用面，而缩小后的适用面仍覆盖了本轮唯一的实际违反
（`:517` 在 §6.4，描述的是「本文件现在是第几轮、本轮做了什么」，属现状自述，不属历史记录）。
边界须在 brief 里写死：**§6.x 条目里描述该条目自身那一轮的措辞获豁免；描述本文件当前状态、
当前轮次、当前节结构的措辞不获豁免，即使它写在 §6.x 内。**

## 四、穷举台账：不再设为验收门

brief 判据 3 要求执行者报告列出全族站点及逐一裁定。执行者没做到。但我认为
**rev7 不应把它再设为阻断门**，理由是它的目的已经由别的途径达成：

- 判据 3 约束的是**报告**，不是交付物。决定能否合入的是文件状态。
- 文件的 INV-S1 状态已被**两次独立扫描**覆盖：我的一签（`grep 'rev[0-9]'` + 「本轮/本文件/
  本交付物/上一轮/本节」+ 序数词族）与 codex 的二签，各自独立扫全文，**都只剩 `:517` 一处**，
  且 codex 还逐一点出了「已同真、不改」的那批（`:3`、`:35–51`、`:151–157`、`:534–603`、
  `:607–626`）。族的封闭性因此已有证据，不需要再靠执行者的台账建立。
- 继续把它设为门，会让 rev7 的失败面从「一个句子」重新扩到「一份台账的完备性」——
  而台账完备性是**难以机械判定**的，等于把一轮窄返工换成一轮开放世界判据。这正是
  `open-world-claims-cannot-be-enumerated` 警告的形状。

rev7 仍要求报告说明改了哪一句、为何新写法对 rev8 成立（这可机械判），
但**不**要求重做全族台账。

## 五、该不该冻第 7 版

两条路都摆出来，我给推荐。

**路 A：冻 rev7，单句返工。**
- 返工面：`:517` 一句，改为不依赖轮数、且与本轮实际动作同真的限定陈述
  （例如「本 rev 不改 §1 证据面与 §2–§5：只收口自指陈述，并按实跑刷新 §7 自核查的数字」）。
- 判据：INV-S1 原文不动 + 新增 §6.x 历史豁免边界 + 明写「本轮自己新增的行同样在适用面内，
  须在编辑定稿后最后扫一遍」+ 保留区判据 4–8 原文照搬。
- 代价：第 7 次冻结、一次派发、一次双签名。
- 风险：低但非零——rev6 证明了「修自指的那一行自己会成为新的自指失效」。
  故判据须显式点破这一点（这是本轮唯一的新增判据内容）。

**路 B：接受 rev6 现状，把 `:517` 登记为已知文档缺陷，不再冻版。**
- 依据：(c′) 已获用户批准，阶段 1 的实质裁定不受 `:517` 影响；该句是修订史里的一句自述，
  不进入任何下游消费。
- 代价：合入一份**已知含一处自指失效**的交付物。七轮的记录里会留下「判据 1 FAIL 但仍合入」。
- 我不推荐：不是因为这一句要紧，而是因为它会让「双签名同判 REWORK 后仍合入」成为先例，
  而这个先例的成本远高于再派发一次的成本。

**推荐路 A。** 三条支撑，都可检：

1. **返工面是七轮最窄且封闭**：一个句子，零取证、零重跑、零设计空间、不动任何证据。
2. **判据不需要重做**：INV-S1 是对的，它抓住了自己引入后才产生的违反。rev7 对判据的唯一
   改动是**缩小**适用面（§6.x 豁免），把 M2 的内部冲突消掉；不新增开放世界要求。
3. **失败的最坏后果仍然有界**：阶段 2 不受阻塞，(c′) 已批，最坏是记录里仍有一句陈旧自述。

**继续沿用的三条约束**（都实测奏效，不撤）：执行面声明（B61）；**双签名并行**
（rev5、rev6 两轮实测独立收敛，rev6 两签阻断项同指一处）；禁止「照抄哈希」修法。

**rev7 新增的第四条约束**：判据须明写「本轮新增的文本在适用面内，须最后扫一遍」，
并要求报告说明新写法为何对 rev8 成立。这是从 rev6 学到的唯一新东西（已登记为 B62 的补充面）。
