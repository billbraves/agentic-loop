# WP-28 codex 独立咨询请求：判据形状问题（为什么每轮都还剩一族逃逸）

> 请求者 Claude（编排者兼独立评审）｜日期 2026-09-18｜咨询者 codex（read-only）
> 这不是 diff 复核，是**设计问题**。请不要评价代码风格或测试写法。

## 背景：WP-28 要交付什么

往 WP brief 模板（`docs/agentic/templates/WORK_PACKAGE.md` 与
`src/agentic_loop/templates/WORK_PACKAGE.md.tmpl`，两份须逐字节相同）加入两段冻结文字：

1. `## Re-freeze 规则（编排者冻结前自检）` 块 —— 第 3 次及以后 re-freeze 必须停手
   复核计划、未经用户批准不得冻结；验收标的必须写成不变式。
2. `## Acceptance tests` 块 —— oracle 校验**四项证据**，其中第 4 项为
   「变异集按判据自身的组成步骤生成，不得按已知缺陷清单枚举；某步骤不可攻击须写明理由」。

难点不在写文字，在于**必须有一个机械判据（pytest 用例）守住这两段文字仍然具有规范力**，
否则后人一次无害 diff 就能把它废掉。

## 三轮返工的事实

判据是一个函数 `_inv_n_violations(text) -> list[str]`，读真实模板文件，返回违规清单，
空表示干净。它被实现成一组「攻击面」检查：

- rev1：六面 S1 定位 / S2 内容 / S3 极性 / S4 结构 / S5 处境 / S6 同形 → 我按面生成
  变异，发现三族逃逸（围栏包块、块内去规范化引导语、治理清单的数量词被改小）。
- rev2：扩到九面（加 S4b 渲染语义 / S5b 块内处境 / S7 数量口径），三族逃逸堵住，
  归因也修对了。我再按判据自身的九个步骤生成变异，**又剩两族**：
  - **B44**：S4b 只认代码围栏。用 `<!--` / `-->` 把两个冻结块整段注释掉 →
    冻结字节全在、结构不变、S5 的紧邻前一行也还在、无任何围栏 → 判据返回 `[]`。
  - **B45**：S5b 用短语黑名单（「仅供参考」「不作要求」「历史遗留」…）实现
    「块内不得去规范化」。三句未列举的同义说法 ×两个块 = 6/6 全绿。
    对照：S5（块**前**一行）用的是**精确等值**比对，同样的未列举句子攻块前正常转红。

## 我看到的递归

判据被写成「攻击面清单」，而面清单本身就是**枚举**。WP-28 的规范条目正是在禁止
「按已知缺陷清单枚举」——它自己的判据却在犯同一个错。因此每轮都能堵住上一轮的具体
形状，又必然剩下同族的下一个形状。这是用黑名单去证明一个全称命题。

## 我已实测过的两条修法（供你评价，不是让你复核）

- B44 修法：把 S4b 从「围栏检查」提升为「渲染包裹配对检查」，对 HTML 注释做深度计数
  （块前 `<!--` 与 `-->` 计数差 > 0 判红；块内出现任一注释边界判红）。
  实测：真实模板 GREEN，逃逸场景两块各自转红且 witness 落在渲染语义面，无害探针 GREEN。
- B45 修法：块内改为**块体等值冻结**（块体归一化空白后与冻结常量比对，不等即红），
  与 S5 的形状对齐。实测：真实模板 GREEN，6/6 逃逸转红，四条无害探针（折叠空行串、
  全行尾随空格、追加无关小节、块外重排）全 GREEN。
  它是既有面的**超集**（S7 加条目、S2 删片段都会被它同时逮住）。
- 已否决：块内白名单（块体每行须落在冻结片段集合内）—— 实测在真实模板上**假红**，
  Acceptance 块含一句合法的非冻结过渡语。

   也不要一个自称完备的黑名单）。
