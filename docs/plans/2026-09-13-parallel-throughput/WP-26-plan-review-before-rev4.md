## 2. 四轮是不是同一个根因

是。四轮全部落在**同一个命题**上：「sha256 锚定的必须是*实际派发*的那份 Brief」。

- B16：锚**路径**没锚对（读了固定命名，不读声明路径）
- B21：锚**在某些分支上根本没执行**（回退分支先 return）
- B25：锚**的测试约束强度不足**（只约束输出形状的一部分）

前三轮各修掉一层，第四层才露出来。这不是执行者反复做错同一件事 —— 每轮增量都通过了
当轮的验收，四轮的失败点互不相同。**根因是我的计划把「锚定」当成一个点状检查，
而它其实是一条链：声明路径 → 分支覆盖 → 约束强度 → 读取同一性。我一次只冻结了链上的一环。**

## 3. 我的计划面失误（这是本次复核的实质产出）

### 失误 1：按「缺陷编号」冻结，而不是按「不变式」冻结

四轮 brief 各自以一个台账编号为标的（B16/B21/B25/B29），每轮范围都只够修那一个编号。
正确做法是一次性把**不变式**写成验收标的：
「从 `evidence.brief.sha256` 校验通过，到执行者手里拿到的正文，中间不得有第二次 I/O，
且所有分支（声明路径 / 回退命名 / 两个消费面）都必须经过校验」。
按不变式冻结，B21/B29 在 rev1 就会被同一条验收要求捕获。

### 失误 2：只审增量，系统性放过前轮引入的缺陷

B29 由 rev1 的提交 `0a12bed` 引入，此后各轮该函数零 diff。三轮咨询 + 三轮编排者验收
的注意力全在本轮增量上，因此三轮全漏。这不是谁不认真，是**审查面选择**的结构性后果。
rev3 我在咨询请求里首次同时给出累计 diff，第二签名当轮就在累计面查出了 B29 —— 反证了
这条因果。**这一条应固化为常规，不是本 WP 的一次性做法。**

### 失误 3：兄弟消费面没有在同一 WP 内收口

同一个「校验对象 ≠ 使用对象」缺口同时存在于两个消费面，我在 rev1 只盯了 python 侧。
两面都在 `allowed_paths` 里，本可一并处理。

## 4. 两个消费面的实测确证（编排者本轮独立复现，不采信任何一方转述）

**python 侧（`redispatch.py:173-187`，B29 本体）**：拦下 `Path.read_text` 使派发面拿到
EVIL 正文、磁盘保持 GOOD 让 `read_bytes` 读到 GOOD。结果：**sha256 校验通过（对 GOOD），
函数返回并将派发 EVIL**。基线（不拦截）返回 GOOD 且校验通过，正向可达。
（注：首次尝试因 macOS `/var` → `/private/var` realpath 差异导致拦截未命中，
按 realpath 比对后复现成立 —— 记此一笔以免后人重踩。）

**bash 侧（`dispatch_lint.sh:125-160`，同族）**：用 PATH 前置一个记录型 `python3` 实证，
该门禁分**两个独立进程**读 brief：进程 A 校验 sha256 后只 `print(real)` 交出**路径**；
bash 用 `sed -n '2p'` 取出路径字符串；进程 B 再 `open(path).read()` **重新读一次**做
section 判据。跨进程边界传递的是路径而非已校验的字节，故「校验对象 ≠ 使用对象」在此
同样成立，且比 python 侧更宽 —— 中间还隔了一次 `[[ -f ]]` 和一次进程启动。
（实证过程中该门禁两次正确拒收了我构造的越界 fixture：相对路径锚到真实主仓、
绝对路径触发 containment 检查。这两条 fail-closed 行为本身是好的，顺手确认。）

## 5. rev4 的范围裁定（本次复核的决定）

**裁定：rev4 一次性收口整条链的「读取同一性」环，两个消费面同时处理，并把验收标的
从缺陷编号改写为不变式。** 理由：两面同族、同在 `allowed_paths`、只修一面则另一面仍在；
且这已是第 3 次 re-freeze，按点状修法继续切分只会招来第 4 次。

rev4 应包含：

1. **python 侧**：`raw = brief_path.read_bytes()` 只读一次，对 `raw` 算 sha256，
   从**同一个** `raw` 解码出返回内容；解码失败规范化为 `BriefIntegrityError`。
2. **bash 侧**：把已校验的**内容本身**交给 section 判据（或让两段判据消费同一次读入的
   字节），不再跨进程传路径。
3. **验收标的改写为不变式**：「校验的字节与交付的字节来自同一次读取」必须有一条用例
   用**拦截/差分**方式正面钉住（不是读代码确认），两个消费面各一条。
4. **不回退**已通过双签名的 B16/B21/B25 修复面；rev3 的断言强度全部保留。
