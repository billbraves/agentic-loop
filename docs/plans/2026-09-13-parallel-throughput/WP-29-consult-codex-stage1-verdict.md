2. 方案 (b) 的可行性结论遗漏了已知的强制 GREEN 约束。

   整份逐字节冻结确实会让 E1–E4 转红，但同样必然让以下合法编辑转红：

   - 修改占位符文字；
   - 文末追加无关章节；
   - 修改 `allowed_paths` 说明；
   - 修改“冻结日期”措辞。

   因而它检测的是“任意字节变化”，不是“活动规范文本失效”。对目标攻击的灵敏度高，但对合法编辑的特异性为零。文中仅把这描述为“更新冻结常量并 review，成本可接受”，没有核对 WP-28 rev3 明确要求这些探针保持 GREEN，故不足以支持阶段 2 冻结。应在方案表中加入这四个反例，并将最终裁定改成与该约束兼容的方案，例如编排者提出的 `(c′)`，或给出一个不会覆盖活文本的精确 envelope。

对阶段 2 的额外约束：文首/文末哨兵不能被描述为拦住 E1/E2“攻击族”。具体绕过如下：

```markdown
<!-- START_SENTINEL -->
<!--
# 后续全部受保护内容
...
-->
<!-- END_SENTINEL -->
```

若判据只验证 sentinel 仍是首尾固定字节，两条 sentinel 都保持原位，而中间规范仍全部失活。未闭合版本也可在 `START_SENTINEL` 后插入 `<!--`，同时保持末尾 sentinel 字节不变。因此哨兵只能阻止“在 sentinel 外侧追加前后缀”的精确形状；要覆盖其内部绕过，仍需冻结明确 envelope 或检查受保护块与边界之间的上下文。E4 继续属于机械承诺边界之外。
