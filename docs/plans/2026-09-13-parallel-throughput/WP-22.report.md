修法：把原先「判定一次、按路径读 N 次」（`:56` `-f`、两处 validator、10 处 `--field`、
`:209` 读旧 JSON）收敛为**单一 probe 进程**——

```
path_is_in_worktree(path)            # WP-19 唯一权威，只引用
  → os.open(path, O_RDONLY|O_NOFOLLOW)   # 只开一次，之后不再按路径解析
  → 按同一 fd 读 → json.loads → validate(data)
  → 抽取全部决策字段 → 一次性以 FINALIZE_PROBE\t<verdict> + KEY\tVALUE 交回 shell
```

判定后被换入的 symlink 在 `open` 时以 `ELOOP` 被拒（新拒收消息
`FINALIZE_FAIL: status file is a symlink`）。probe 是普通赋值，崩溃即 `set -e`
中止（fail-closed，A29 口径）。

## 3. oracle 三项在本轮的落实

五个用例**每一个**都自带三项，非仅 `rc != 0`：

| oracle 项 | 落实方式 |
|-----------|----------|
| 正向可达性对照 | 每条用例末尾在**同一 fixture** 上换成正常主区真文件重跑，断言 `FINALIZE_OK merged_commit=<merge_commit>` 且 `state == MERGED`（:192-198、:236-237、:278-280、:305-307）→ 证明前置条件确实能到达终点，拒收不是「本来就到不了」 |
| 原因特异 witness | 断言具体 `FINALIZE_FAIL` 串（`symlink` / `worktree` / `not found`）、`FINALIZE_OK` 不在 stdout、**伪造副本未被改写**（`state` 仍 `APPROVED_FOR_MERGE`、`evidence.tests[0].command` 仍是 `FORGED_WORKTREE_COPY`、`git` 无 `merged_commit`）、无 `Traceback`（:176-186、:221-229、:267-272、:295-299） |
| 代表性禁止变异转红 | 摘掉 `O_NOFOLLOW` → 目标用例转红并复现攻击结果（编排者独立执行，见上） |

四条拒收语义逐条留测试且全部保持：worktree 内路径拒收、指向 worktree 副本的
symlink 拒收、不可解析路径 fail-closed 且不抛异常、主区真文件不回归。

   「写回不会写错文件」与「写回读到的旧 JSON 可能已被换」是两件事，前者已证，
   后者未证。已登记待办（见 §6）。

## 5. 残余风险

1. `O_NOFOLLOW` 的语义边界：只拒最后一段是 symlink，中间目录段被替换仍可被跟随
   （Brief 附注 4 已声明，本轮不修）。
2. 写回段 `:328` 按路径重读旧 JSON 的窗口未关（CONCERN 2）；写回**落点**已证免疫，
   但写回**读取内容**的新鲜度未证。
3. probe 把 10 处 `--field` 调用换成一份内联的字段抽取实现—判据语义已逐行核验同义，
   但这是**第二处**渲染逻辑（§5.3 的边缘）。它没有第二份可执行**口径**（校验规则仍
   唯一来自 `validate()`），但渲染若日后在 `main()` 一侧漂移，probe 不会自动跟随。
