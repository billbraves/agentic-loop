## 4. Brief 的一处错误（**错在编排者，不在执行者**）

冻结 Brief 的交付物第 5 条与 `Acceptance tests` 段要求 witness 用例断言报的是
`empty` 而**不是** `missing`。这条要求**不可能成立**：

```
dispatch_lint.sh:86   print(f"brief missing section '{heading}'")   # 标题缺失
dispatch_lint.sh:98   print(f"brief missing section '{heading}'")   # 标题在、段内空
```

真 gate 两条失败路径打印**同一句** `missing`，全脚本不含 `empty` 一词。
`empty` 来自我上一轮为登记 B10 而**抄出来的一份 `lintcheck.py` 副本**里自造的措辞
（该副本 :7 `FAIL missing`、:12 `FAIL empty`），我把副本的输出当成真 gate 的输出
写进了冻结 Brief 的必达断言。

这正是 Brief 自己第 4 条陷阱禁止的形态：**抄副本 = 测副本**，也是 B9「观测通道选错」
的同族——判定通道（我的副本）与结论（真 gate 的行为）之间隔着一条未核验的等价假设。
已另立缺陷 B11 登记（见 `WP-08-candidate.md`）。

执行者的处理是正确的：
- 在 `[CONCERNS]` **显式申报**了这条不可达，而非默默照做或默默跳过；
- 用等价的三段证据链替代（段内非空那一半判据仍被单独证明活着）；
- 没有为了让断言成立去改 `dispatch_lint.sh`（那是 forbidden path、零改动项）。

按「Brief 冻结但 Brief 有错时以真实判据为准，且要求执行者申报」的口径，此处判 **ACCEPT**，
不判 REWORK。
