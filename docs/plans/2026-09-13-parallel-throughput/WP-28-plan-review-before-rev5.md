## 2. 本轮唯一阻断项的根因，以及它是不是计划面的

rev4 只剩一个阻断项：M-T0 / M-T0b 变异内存字符串而非文件字节，撤销 fix 后仍全绿。

**根因是计划面的，而且是我上一轮复核留下的。** rev4 前置复核（§2）把根因判为
「变异集的生成范围划在比较逻辑上，没划在完整管线上」，并据此在 brief §A.4 要求
「新增变异 M-T0：两份模板同步把全部 `\n` 改为 `\r\n`」。

那句话有歧义，而歧义方向恰好落在缺陷侧：「两份模板」既可读作模板**文件**，
也可读作判据从模板读出的**字符串**。执行者取了后者 —— 且 §A.4 第 3 条要求它
「须经 `_mutate_both()` 的统一 no-op guard」，而 `_mutate_both()` 的签名就是
`mutate(str) -> str`，等于把实现推向内存变异。**我一边要求攻击读路径，
一边指定了一个跨不过读路径的载具。**

所以这不是执行者理解偏差。rev4 的 §A.4 在「变异施加点」上欠一句话，
而这一句话正是本 WP 标的的下一层。
